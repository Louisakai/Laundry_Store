# WORKLOG — Laundry Backend (2026-08-03)

Tổng kết toàn bộ công việc trong ngày dành cho API **laundry-be** (NestJS + TypeORM + Socket.IO).

## 1. REQLOG middleware

`src/main.ts`: thêm middleware log mọi request tới console dưới dạng:
```
[REQLOG] <ISO time> <METHOD> <originalUrl> -> <statusCode> from <ip>
```
- Mục đích: gỡ lỗi luồng gọi API từ mobile app (đặc biệt điều tra lỗi nút "Đăng nhập" không kích hoạt handler — xác nhận app KHÔNG gửi request tới backend).
- Chạy trong nhánh bootstrap trước khi khởi động `AppModule`, áp dụng cho toàn app.

## 2. Sửa thứ tự route trong StaffController

`src/staff/staff.controller.ts`:
- **Vấn đề cũ:** các route động `GET/PATCH/DELETE staff/:id` (admin) được khai báo TRƯỚC các route tĩnh → trong NestJS, `GET staff/:id` nuốt mất `GET staff/orders`, khiến route tĩnh bị shadow (không bao giờ tới).
- **Fix:** bỏ các route admin `findOne` / `update` / `remove` khỏi controller này (chỉ giữ `POST staff` cho admin), đảm bảo các route tĩnh `staff/orders`, `staff/location`, `staff/orders/:id/complete`, ... không bị nuốt. Thêm comment ghi chú quy tắc thứ tự.
- Định dạng lại body DTO cho rõ ràng (prettier).

## 3. Unit test cho thứ tự route

`src/staff/staff.controller.spec.ts` (mới): dùng `@nestjs/testing` + `supertest`, mock `JwtAuthGuard`/`RolesGuard` pass qua, kiểm tra:
- `GET /staff/orders` không bị `GET staff/:id` shadow → trả về `[{ id: 'order-1' }]`.
- `PATCH /staff/location`, `POST staff`, `GET staff/:id` hoạt động đúng route.
